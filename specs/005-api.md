# SPEC 005 — API REST (Contratos)

Prefixo `/api/v1`. Toda rota autenticada salvo `@Public()`. Validação de body/query/params por schemas Zod do `packages/shared` (pipe global). Paginação padrão: `?page=1&perPage=20` → `{ data, meta: { page, perPage, total, totalPages } }`. Erro padrão: `{ statusCode, error, message, details? }`. Cada endpoint documentado em `docs/api-reference.md` com exemplo `curl` + resposta real.

## Auth
```
POST /auth/login            { email, password, tenantSlug? } → { accessToken, user }  (+ cookie refresh)
POST /auth/refresh          → novo par (rotação)
POST /auth/logout
GET  /auth/me               → perfil + branch + completedTours
```

## Users (ADMIN)
```
GET    /users?search=&page=
POST   /users               { name, email, password, role, branchId? }
PATCH  /users/:id           (nome, role, branchId, isActive)
```

## Branches (leitura — escrita é via scripts, spec 002)
```
GET /branches               → filiais ativas do tenant (para seletores e mapa interno)
```

## Customers & Equipments
```
GET    /customers?search=&page=
POST   /customers · GET /customers/:id · PATCH /customers/:id
GET    /customers/:id/orders
POST   /customers/:id/equipments · PATCH /equipments/:id
```

## Service Orders
```
GET    /orders?status=&branchId=&technicianId=&priority=&search=&page=
        → técnicos com filial fixa: branchId forçado; busca cobre code, cliente, equipamento
POST   /orders              { branchId, customerId, equipmentId, reportedIssue, priority, promisedAt? }
GET    /orders/:id          → OS + cliente + equipamento + quote ativa + filial
GET    /orders/:id/events   → trilha de auditoria (asc)
PATCH  /orders/:id          → campos editáveis variam por estado (diagnóstico só até QUOTE_SENT etc.)
POST   /orders/:id/assign   { technicianId }
POST   /orders/:id/transitions   { action, payload? }   ← ÚNICO ponto de mudança de status (ADR-006)
        payload por ação: CANCEL { reason } · REJECT_QUOTE { reason } · etc.
POST   /orders/:id/warranty-reopen   → cria OS filha (RN-07), retorna a nova OS
```

## Quotes
```
POST   /orders/:id/quotes        → nova versão DRAFT (falha se já existe DRAFT/SENT ativa)
PATCH  /quotes/:id               → itens em lote enquanto DRAFT; recalcula totalCents na transação
POST   /quotes/:id/send          → atalho para transition SEND_QUOTE
```

## Público (`@Public()` + rate limit 20/min/IP)
```
GET  /public/quotes/:token       → empresa(nome/filial), OS resumida, itens, total, validade
                                   (token expirado → 410; inexistente → 404 genérico)
POST /public/quotes/:token/approve
POST /public/quotes/:token/reject   { reason }
GET  /public/map/:mapToken       → { tenantName, branches: [{ name, address, city, phone, lat, lng }] }  (RN-15)
```

## Dashboard
```
GET /dashboard/summary?branchId=&from=&to=
     → { openOrders, overdueOrders, revenueCents, avgTicketCents,
         quoteApprovalRate, avgRepairTimeHours, deliveredCount }
GET /dashboard/orders-by-status?branchId=
GET /dashboard/revenue-by-month?months=6&branchId=
GET /dashboard/branches-comparison        → ADMIN: tabela comparativa por filial
```
Definições (documentadas em `docs/business-rules.md`): receita = soma de quotes APPROVED de OS DELIVERED no período (pela `deliveredAt`); tempo médio de reparo = `deliveredAt - createdAt` médio; atrasada = `promisedAt < now` e status não-terminal.

## Assistente (spec 010)
```
POST /assistant/chat              { messages } → streaming SSE
POST /assistant/dashboard-insights { branchId?, from?, to? } → { insights: string[] }
```
